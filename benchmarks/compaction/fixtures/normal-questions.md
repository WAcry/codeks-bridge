# normal fixture 的确定性问卷

`normal-questions.json` 只定义检查点产物的独立问答验证。答题请求在固定公共指令和工具声明之后，只携带被测产物和 `quiz`，不携带 `normal.json` 的原始线程、保留消息、gold facts、答案或 evidence。压缩生成阶段使用原始线程，不等于答题阶段可以再次看到它。

共 93 题，覆盖原始 F01–F50，另外记录两个直接来自线程的事实。每题使用数值、布尔值、准确标识符、明确选项或小型 JSON 对象。字符串数组中无意义的顺序由 `unordered: true` 标记；journal 操作顺序保留顺序要求。题目中的枚举仅用于约束答案表示，不把某个选项声明为已知事实。

`quiz` 由固定答题说明与每题的 `id`、`question` 拼接；没有复制 `expected`、`fact_ids`、`category`、`evidence`。`evidence.item_index` 是 `normal.json.thread` 的零基索引，`quote` 必须是该条原文的连续片段。区间 evidence 用于标注检查点末尾没有修改动作、完整线程没有某个值等范围判断。

问卷明确区分最终默认值和初始建议、旧 CLI 参数和当前参数、曾获准本地提交和最新暂停提交、当前实现与待修复问题、最终 review 前的测试结果与之后尚未完成的工作。F40–F42 的修复状态还由 F47、F50 的检查点问题交叉覆盖。

四个缺失值问题使用 `null`：后续真实 smoke 的租户标识、S1 耗时、Windows 验证环境版本、包含最终修复的提交 SHA。已知空集合使用 `[]`，不能与未知值混同。没有从示例租户、一般平台常识、尚未执行的动作推断答案。

额外事实只属于这份问卷，不修改原 fixture 的 gold facts：

- F51：capabilities 的上下限字段准确拼写为 `minimum_chunk_bytes` / `maximum_chunk_bytes`，值分别为 1048576 / 16777216；来源是 thread[9] 和 thread[80]。
- F52：发现响应格式异常或协议不受支持时，在 begin 前失败，不猜默认值；来源是 thread[78]。

覆盖表中的“覆盖”表示存在问题，不能等同于模型通过。题级 JSON 全等意味着一题含多个子字段时须全部正确才通过，93 题得分也不能直接解释成 50 项事实的保留比例。枚举问题仍有猜中的可能；这份合成线程问卷衡量事实恢复和状态区分，不代替真实后续开发表现。

静态验证核对所有 evidence 引文、连续且唯一的问题 ID、完整事实映射、无序数组类型、quiz 投影和原 fixture SHA-256。未调用模型 API，也未把答案加入被测请求。
