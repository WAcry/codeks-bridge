1. Primary Request and Intent

Implement resumable parallel directory uploads in Driftship, a TypeScript CLI, in /work/driftship on branch feature/resumable-upload. Preserve the command shape:

driftship push <directory> --to <url>

Requirements established across the conversation:

- Node 22 or later, zero runtime dependencies.
- Default four workers, 4 MiB chunks, four retries meaning four additional attempts after the initial PUT attempt.
- User concurrency range 1–16; effective concurrency is min(requested concurrency, server maximum_parallel_parts). Requested 2 must remain 2.
- Authenticate discovery and writes using DRIFTSHIP_TOKEN.
- Discover and validate protocol 3 capabilities before begin. Malformed discovery or another protocol fails without guessed defaults.
- Resume defaults on. Final flag syntax is --resume=on|off; reject verify and remove --no-resume entirely.
- Journal at <source>/.driftship/resume-v1.json. Durable serialized updates, no database or dependency.
- Resume identity includes full SHA-256, file size, nanosecond mtime, and compatible chunk size.
- Validate remote file_size, file_sha256, and part_size before accepting resumed state, including completed sessions.
- Missing/expired remote sessions may restart automatically. Inconsistent existing sessions fail with session_mismatch.
- Retry only idempotent PUT parts. Never automatically retry begin or complete.
- An ambiguous complete failure permits one GET status. If GET fails, return that error and let the next invocation resume.
- Dry-run makes zero network calls and creates no .driftship directory.
- Cancellation exits 130, stops new scheduling, aborts requests, and settles queued journal writes.
- JSON events retain type and gain one UUID run_id per invocation. Completion includes files, bytes, uploaded_bytes, resumed_bytes. Uploaded bytes count confirmed unique bytes, excluding retransmission traffic.
- Users must not modify the source tree during upload; detected changes fail. Atomic snapshots, locks, copy-on-write, and watchers are out of scope.
- Local development/testing only. No remote publication, push, merge, cleanup, or real-service credential discovery.

  import { setTimeout } from 'node:timers/promises';
  export interface RetryOptions {
    retries:number; signal:AbortSignal;
    now?:()=>number; random?:()=>number;
    sleep?:(ms:number,signal:AbortSignal)=>Promise<void>;
    onRetry?:(attempt:number,delayMs:number)=>void;
  }
  export function retryDelay(header:string|null,now:number):number|undefined {
    if(!header)return undefined;
    const seconds=Number(header);
    if(Number.isFinite(seconds)&&seconds>=0)return seconds*1000;
    const date=Date.parse(header);
    if(!Number.isNaN(date))return Math.max(0,date-now);
    return undefined;
  }
  export async function retry<T>(
    operation:(attempt:number)=>Promise<T>,
    classify:(e:unknown)=>{retry:boolean;after?:string},
    options:RetryOptions
  ):Promise<T> {
    const now=options.now??Date.now, random=options.random??Math.random;
    const sleep=options.sleep??((ms,signal)=>setTimeout(ms,undefined,{signal}));
    for(let attempt=0;;attempt++) {
      options.signal.throwIfAborted();
      try {return await operation(attempt);}
      catch(error) {
        const decision=classify(error);
        if(!decision.retry||attempt>=options.retries)throw error;
        const after=retryDelay(decision.after??null,now());
        const base=Math.min(30000,500*2**attempt);
        const delay=after??Math.floor(base*(0.5+random()*0.5));
        options.onRetry?.(attempt+1,delay);
        await sleep(delay,options.signal);
      }
    }
  }
