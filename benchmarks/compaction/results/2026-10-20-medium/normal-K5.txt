- Current `src/retry.ts` as last read:

```ts
import { setTimeout } from 'node:timers/promises';

export interface RetryOptions {
  retries: number;
  signal: AbortSignal;
  now?: () => number;
  random?: () => number;
  sleep?: (ms: number, signal: AbortSignal) => Promise<void>;
  onRetry?: (attempt: number, delayMs: number) => void;
}

export function retryDelay(header: string | null, now: number): number | undefined {
  if (!header) return undefined;
  const seconds = Number(header);
  if (Number.isFinite(seconds) && seconds >= 0) return seconds * 1000;
  const date = Date.parse(header);
  if (!Number.isNaN(date)) return Math.max(0, date - now);
  return undefined;
}

export async function retry<T>(
  operation: (attempt: number) => Promise<T>,
  classify: (e: unknown) => { retry: boolean; after?: string },
  options: RetryOptions,
): Promise<T> {
  const now = options.now ?? Date.now, random = options.random ?? Math.random;
  const sleep = options.sleep ?? ((ms, signal) => setTimeout(ms, undefined, { signal }));
  for (let attempt = 0;; attempt++) {
    options.signal.throwIfAborted();
    try {
      return await operation(attempt);
    } catch (error) {
      const decision = classify(error);
      if (!decision.retry || attempt >= options.retries) throw error;
      const after = retryDelay(decision.after ?? null, now());
      const base = Math.min(30000, 500 * 2 ** attempt);
      const delay = after ?? Math.floor(base * (0.5 + random() * 0.5));
      options.onRetry?.(attempt + 1, delay);
      await sleep(delay, options.signal);
    }
  }
}
```

User requirements and decisions already established

Protocol, parallelism, retries:
- Server protocol must be exactly 3.
- Malformed discovery or a different protocol must fail before begin, with no guessed defaults.
- Default four workers and 4 MiB chunks to match server.
- Concurrency setting accepts integers 1–16.
- Effective concurrency = min(user setting, server `maximum_parallel_parts`); requested 2 must remain 2.
- Four retries means four additional attempts after the initial attempt, five total.
- Only idempotent PUT part requests may retry.
- Never automatically retry begin or complete.
- One GET status after an ambiguous complete failure is allowed.
- If that GET fails, return its error and let the next invocation resume.
- Handle lost part responses where data persisted before socket failure.
- Handle successful completion followed by lost response.
- No duplicate objects or skipped parts.
- Remote cleanup is out of scope. Earlier discussion of deleting stale sessions was brainstorming, not authorization.

Resume and journal:
- Journal path is `.driftship/resume-v1.json` inside the source directory.
- Resume enabled by default.
- CLI flag is `--resume=on|off`; reject `verify`.
- Old `--no-resume` must not be retained as alias.
- `--resume=off` starts fresh locally and must not delete or abort remote sessions.
- Durable journal is important for interrupted writes on removable media.
- Serialize writes without a dependency or database.
- Resume file identity must include full SHA-256, size, and nanosecond mtime; full read cost is acceptable.
- Validate remote status size, SHA-256, and part size before accepting resumed state.
- Remote mismatch means `session_mismatch`.
- Only missing/expired remote sessions restart automatically.
- Snapshots, locks, copy-on-write, and watchers are out of scope.
- Users must not modify the source during upload; detected changes must fail.
- Cancellation must settle queued journal writes without scheduling new upload work and exit 130.

Destination/auth/errors:
- Reject URL query parameters, fragments, and userinfo.
- Only trailing slash normalization is allowed.
- Authentication remains in `DRIFTSHIP_TOKEN`.
- Errors must not echo supplied URL or token.

Dry-run:
- Zero network calls.
- Must not create `.driftship`.
- Scanning for plan totals is allowed.
- May report requested rather than effective concurrency, because discovery is forbidden.

Events and accounting:
- One UUID `run_id` generated once per invocation and included in every JSON event.
- Keep `type` as discriminator; do not rename to `event`.
- Completion event includes `files`, `bytes`, `uploaded_bytes`, `resumed_bytes`.
- Uploaded bytes count unique confirmed bytes, not retransmission traffic.

Exit codes:
- 0 success.
- 1 transport/server or ordinary local I/O failure.
- 2 usage/configuration.
- 3 invalid or mismatched local resume state.
- 130 interruption.
- Server checksum mismatch uses 1.
- `session_mismatch` uses 3.
- Ordinary permission failures must not be classified as 3.
