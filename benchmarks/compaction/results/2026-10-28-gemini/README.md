# Gemini 4 Argon / high：两种摘要 prompt 对照

本轮结果支持 **Gemini 继续使用当前 bridge summary prompt**：已完成的高密度摘要均能恢复全部受测事实；开发任务中，标准版 S 为 **251/267（94.01%）**，Antigravity 版 A 为 **244/267（91.39%）**。A 在开发材料上更短，但遗漏了更多错误处理、字段和重试参数。这里只有一个开发任务的三个重复，不足以证明所有任务上的稳定排序。

S 的一个高密度样本两次请求均在传输阶段失败，没有完整摘要；不能把它算成满分，也不能由超时推定摘要内容差。报告保留全部失败，不删除本轮任何已完成的低分样本。跨模型历史对照同时列出完整批次与旧报告的七样本口径。

## 路线、材料与评分

| 路线 | 生成请求 | 产物 |
| --- | --- | --- |
| S | 完整历史 H + [当前 bridge summary](../../prompts/bridge-summary.txt) | 文字摘要 |
| A | 完整历史 H + [用户提供的 Antigravity prompt](../../prompts/antigravity.txt) | 文字摘要 |

生成者和读者均为 **Gemini 4 Argon / high**，原生 `streamGenerateContent`、`thinkingLevel=HIGH`，经 bridge 转换；没有设置输出 token 上限。A 的来源是用户提供的英文文本，不声称核验了某个 Antigravity 发布版本。生产 prompt 不变，实验使用冻结快照。[plan.json](plan.json) 固定模型、参数、顺序和全部输入 hash。

**每次最终问答只带对应 K、固定公共指令和题目，不带 H、保留用户消息 U、生成 reasoning、其他路线的摘要或答案。** 摘要生成请求不含题目或标准答案。输入历史没有 reasoning items，但包含真正的协议工具调用及结果：高密度材料每份 540 个 items、200 对调用/结果；开发材料 103 个 items、42 对调用/结果，不是把工具输出拼成用户叙述。

- 高密度：复用[旧 fixtures](../2026-10-20/fixtures/)的八个 seeds，每份 1,000 条记录；每次 150 道已知事实题和 5 道无答案题。
- 开发任务：同一份虚构 TypeScript 上传 CLI 历史，独立生成三次；每次 89 道已知事实题和 4 道无答案题。这是一个任务的重复，不是三个独立任务。
- 逐值精确评分；题目约定的无序集合忽略排列，缺字段不等于正确的 `null`。无答案题另算，不混入已知题正确率。
- 严格 JSON 与内容评分分别保存。内容评分只允许移除一层完整外部 JSON 围栏，不修补答案。本轮全部新回答都是裸 JSON，两种分数完全一致。
- 完整 H 对照使用 `auto`；空历史对照与 K-only 问答使用 `none`，不执行工具。所有九份完整 H 对照合计 **1,289/1,289**；三个成功的空历史高密度对照 **0/450**，其余六个空历史对照失败。

S 与历史 GPT、Opus 的 K2 **并非同一 prompt**。旧 K2 使用完整 Claude Code 式文本，要求独立列出所有真实用户消息；当前 S 取消这个清单，仍要求保留用户意图、权限、安全约束，并简化工具禁用措辞。不能把旧 Opus K2 的成绩直接称为当前 S 的实测成绩。

### 开发材料丢了什么

六份摘要对应的回答都正确保留了权限、安全要求、review 项、下一步和当前工作状态：修复仍待执行、最后只是读取重试代码、没有提交授权、没有发布、真实服务的生产可用性尚未验证。S 的这些类别合计 75/75，A 也是 75/75；不能据此声称所有范围约束都完整保留。

| 例题 | 原事实 | 观察 |
| --- | --- | --- |
| Q026 | 对账 GET 自己失败时应返回 `status_get_error` | A 的前两份省略该规则，读者答成 `original_complete_error`；S 保留并答对。这可能影响后续实现。 |
| Q028 | receipt 字段是 `path, bytes, sha256, etag` | A 前两份没有完整字段；回答出现 `size` 或 `null`。S 也并非每份都保留。 |
| Q082 | fallback 为 500ms、倍增 2、base cap 30,000ms、jitter 0.5–1 | A 三份均未完整恢复，第三份把 cap 答成 4,000ms；S 保留了对应完整代码。 |
| Q040 / Q041 | 旧并发探针字节数 17,825,900 / 22,020,204；峰值 4、PUT 7、唯一 part 6 | 两种路线均常遗漏旧测量，保留“运行过探针”不等于保留测量值。 |
| Q043 | 范围排除 snapshots、file locks、copy-on-write、watchers | 部分摘要漏掉 copy-on-write；整个范围类别 S 5/6、A 4/6，不是范围无损。 |
| Q001 | 项目名 `Driftship` | 部分读者输出 `driftship`；摘要中其实保留了正确大小写。这是读者/精确匹配失分，不能归为摘要遗漏。 |

A 更强调立即接手，开发 K 比 S 短；差距既包含可重新获取的旧测试与测量，也包含仍有实现价值的字段和错误处理，不能一概说成有意删除低价值信息。这里没有让接手模型真正完成开发，不能直接推定最终编程成功率。

空历史对照失败不代表摘要丢失内容。首次高密度 S 生成完成 7/8，首次完整问答 6/8；保留原 K 重试后问答为 7/8。A 高密度首次即 8/8；开发 A 首次问答 2/3，原 K 重试后 3/3，S 开发首次 3/3。共 18 次对照、23 次生成尝试、23 次恢复尝试。

三次人工重试都因已观察到的流空闲超时，body SHA-256 与原请求完全一致；没有替换弱产物或错误答案。重试政策是在看到超时后作出的操作调整，不声称预先注册；通用 runner 本身仍不自动重试。[results.json](results.json) 保留原失败、人工重试、耗时、请求体 hash 和最终引用关系。

### 前缀相同，不代表已证实 cache hit

本轮保留相同 system、tools、thinking 设置和 H，S/A 只追加各自摘要指令，先后顺序按案例交替。逐请求核对原生 JSON 后，共同前缀逐字节一致。完整 H 对照后先运行空历史对照，再开始摘要；因此它并非总是紧邻生成的预热，空历史超时还会延长间隔。两组材料批次重叠，各至多两个活跃案例，没有额外发送无任务的暖身请求。

本轮仅使用原生隐式缓存，没有创建显式 `cachedContents` 或设置 TTL。可取得最终原生 usage 的 **59 次响应全都没有 `cachedContentTokenCount` 字段**；bridge 将缺省映射为 0，所以记录中的缓存输入为 0。准确结论是 **没有测到可证明的缓存命中**，不能由缺字段断言物理上每次都 miss，也不能宣称已经达到高命中。缓存行为参考 [Gemini 缓存文档](https://ai.google.dev/gemini-api/docs/generate-content/caching)；这轮材料不是完整真实工作会话的缓存性能测试。

## 必要的 Gemini 消息边界修正

首次完整历史诊断发现：最后一个工具结果与新用户指令被拼进同一个 `Content.parts`，受测路由返回 400 `Requests ending with a model turn are not supported.`。极小合成对照中，混合写法同样 400；保持两个相邻 user Content、先 functionResponse 再新指令，则成功返回 `READY`（input 113、output 5）。不能仅凭错误文本推定是所有 Gemini 服务的普遍限制或某个中间服务的确定根因。

本轮使用提交 `f63ea859d022d7fb42c12710f2d9f419f47cfa07`：adapter 保留工具结果与随后新指令的边界，仍按调用顺序聚合同一批并行工具结果。变更、文档与回归测试一起提交。上述四次前置诊断包含一次取消的空历史请求，不纳入主实验质量与用量；取消请求没有最终 usage。

## 复现与核验

使用当前 bridge 的 Gemini 原生连接，在仓库外配置端点和鉴权。runner 的 `BENCHMARK_URL` 为 bridge `/v1/responses` 完整 URL；`BENCHMARK_HEADERS` 在环境中传入，计划与公开产物均不含凭据。

```sh
# 先核对输入 hash 并查看计划；不调用网络。
node benchmarks/compaction/compare-prompts.mjs \
  --plan benchmarks/compaction/results/2026-10-28-gemini/plan.json \
  --out benchmarks/compaction/runs/gemini-high

# 添加 --execute 才实际运行；每次使用新输出目录。
node benchmarks/compaction/compare-prompts.mjs \
  --plan benchmarks/compaction/results/2026-10-28-gemini/plan.json \
  --cases normal-r1,normal-r2,normal-r3 \
  --out benchmarks/compaction/runs/gemini-normal --execute

node benchmarks/compaction/compare-prompts.mjs \
  --plan benchmarks/compaction/results/2026-10-28-gemini/plan.json \
  --cases stress-3617031,stress-3617032,stress-3617033,stress-3617034,stress-3617131,stress-3617132,stress-3617133,stress-3617134 \
  --out benchmarks/compaction/runs/gemini-stress --execute

# 离线重算公开记录，不调用模型。
node benchmarks/compaction/verify-record.mjs \
  benchmarks/compaction/results/2026-10-28-gemini
```
