1. **Task Overview**
   - **Goal**: Add resumable parallel uploads to the Driftship TypeScript CLI (`driftship push <directory> --to <url>`) in `/work/driftship` on branch `feature/resumable-upload`.
   - **Runtime & Dependencies**: Node 22 or later (`"engines": {"node": ">=22"}`), zero runtime dependencies (`"dependencies": {}`).
   - **Core Specifications**:
     - **Concurrency & Chunks**: Default 4 concurrent requests (`--concurrency` 1–16; effective concurrency is `min(user setting, server maximum_parallel_parts)`, bounded globally across the push), 4 MiB chunks (`--chunk-mib` 1–16, default `4194304` bytes, validated against server capability bounds), and 4 retries (`--retries` 0–12, default 4 extra attempts = 5 total attempts).
     - **Resume & Journal**: Local journal at `<directory>/.driftship/resume-v1.json`. Controlled via `--resume=on|off` (default `on`; reject `verify` or other values; do NOT support `--no-resume`). `--resume=off` starts fresh locally and must never delete or abort remote sessions/objects.
     - **Durability**: Create `.driftship` with mode `0700`, write temp file `.resume-<uuid>.tmp` with mode `0600`, `fsync` file, `rename` over `resume-v1.json`, and `fsync` parent directory. Serialize all in-memory mutations and disk writes through `JournalStore`.
     - **Security & URLs**: Read token from `DRIFTSHIP_TOKEN` (`Authorization: Bearer <token>`). Never leak token or raw supplied URLs into journals, stdout/stderr, or error messages. Reject HTTP redirects (`redirect: 'error'`). Reject URL userinfo, query parameters, and fragments; normalize only a trailing slash.
     - **Protocol & Retries**: Validate `GET capabilities` (`protocol === 3`, `sha256` support, positive integer chunk/parallel bounds) before `begin`. Only idempotent `PUT uploads/{id}/parts/{part}` requests retry (on `408, 429, 500, 502, 503, 504` or network `TypeError`, honoring `Retry-After` delta-seconds or HTTP-date). Never retry `begin` or `complete`. On ambiguous network `TypeError` during `complete`, perform one `GET uploads/{id}` reconciliation read.
     - **Source & Session Identity**: Full file SHA-256, `size`, nanosecond `mtimeNs`, and `chunkBytes`. Validate remote session `file_size`, `file_sha256`, and `part_size` (`session_mismatch` on mismatch; only missing `404` or `expired` sessions restart automatically).
     - **Dry-run**: `--dry-run` scans locally, makes zero network calls (skipping capability discovery), and creates no `.driftship` directory.
     - **JSON Output & Exit Codes**: In `--json` mode, emit one JSON object per stdout line with `type` discriminator and a single UUID `run_id` per invocation. `complete` includes `files`, `bytes`, `uploaded_bytes` (confirmed unique bytes, excluding retransmission wire bytes), and `resumed_bytes`. Exit codes: `0` success, `1` transport/server/checksum/local I/O error, `2` usage/config/unsupported protocol, `3` invalid or mismatched resume state (`journal_invalid`, `journal_unsupported`, `destination_mismatch`, `session_mismatch`), `130` `SIGINT` interruption (stops scheduling, aborts in-flight requests, and settles already-queued journal writes).

3. **Key Findings**
   - Server protocol revision 3 caps `maximum_parallel_parts` at 4 and prefers 4 MiB chunks (`1 MiB` min, `16 MiB` max). Empty files use `begin` + `complete` with `parts: []` and zero `PUT` part requests.
   - In V8/Node, `Date.parse("-1")` evaluates to a valid timestamp rather than `NaN`, causing `retryDelay("-1", now)` in `src/retry.ts` to return `0` instead of `undefined` (finding R1).
   - In `src/push.ts`, when resuming a file whose remote status is `complete`, the code validated the receipt without first calling `validateSession(status, saved)` (finding R2).
   - `README.md` still contains `--no-resume` in its first example (finding R3).
