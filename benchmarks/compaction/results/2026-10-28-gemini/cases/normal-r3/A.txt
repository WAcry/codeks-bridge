3. **Key Findings**
   - **Server Protocol v3 (`docs/server-protocol.md`)**:
     - `GET capabilities` returns `protocol: 3`, `minimum_chunk_bytes: 1048576` (1 MiB), `maximum_chunk_bytes: 16777216` (16 MiB), `preferred_chunk_bytes: 4194304` (4 MiB), `maximum_parallel_parts: 4`, `checksums: ["sha256"]`.
     - Empty files (`size === 0`) use `begin` and `complete` with `parts: []` and empty-bytes SHA-256 (`e3b0c44298fc1c14...`), with zero `PUT` part calls.
     - Object paths use URI-encoded path segments (`parts.map(encodeURIComponent).join('/')`), preserving Unicode normalization (NFD vs NFC) and literal `%` as `%25`.
   - **Final Review Findings (`node scripts/review-final-diff.ts`)**:
     - **R1 (MUST FIX)**: In `src/retry.ts`, `retryDelay("-1", now)` fails the `seconds >= 0` check and falls through to `Date.parse("-1")`, which in V8 parses as a valid past date (`2001-01-01`) and returns `Math.max(0, date - now) === 0` (0 ms delay) instead of `undefined` (exponential backoff fallback). `integration/generated/protocol-03.test.ts` (`retry-negative`) only asserted `Number.isFinite(delay)` instead of asserting fallback to positive backoff delay.
     - **R2 (MUST FIX)**: In `src/push.ts`, when `status.state === 'complete'`, the code validates the receipt and takes the fast path *before* calling `validateSession(status, saved)`. If a remote completed session has mismatched `file_size`, `file_sha256`, or `part_size`, it skips `validateSession`. `validateSession` must run for both `'complete'` and `'open'` states.
     - **R3 (MUST FIX)**: `README.md` still references `--no-resume` in its first example instead of `--resume=off`.
     - **R4 & R5 (FOLLOW-UP)**: File descriptor reuse to narrow source-change races (R4) and lazy session creation for huge file counts (R5) are non-blocking follow-ups to record in `docs/development-notes.md`.
     - **R6 (DOCUMENT)**: CLI argument parsing errors happen before `--json` is known, so usage/parse errors are emitted as plain text on stderr. Document this boundary in `docs/json-events.md` (and/or `docs/development-notes.md`).

4. **Errors & Fixes**
   - **Concurrent journal update race & destination query acceptance** (`npm test` initial run: 2 failures):
     - *Cause*: Workers wrote stale snapshots concurrently; `destinationKey` stripped `url.search` and `url.hash` without rejecting them.
     - *Fix*: Added `src/journal-store.ts` (`JournalStore`) to serialize updates on a promise chain and added `directory.sync()` in `src/journal.ts`. Updated `validateDestination` in `src/path.ts` to reject `username`, `password`, `search`, and `hash` before normalization.
   - **Recovery test failures (`resume-complete` and `complete-lost` in `integration/recovery.test.ts`)**:
     - *Cause*: Completed sessions still posted `/complete`; socket resets during `/complete` threw `TypeError` without checking remote status.
     - *Fix*: Handled `status.state === 'complete'` in `src/push.ts` by validating `status.receipt` directly; in `src/complete.ts`, caught non-`HttpError` `TypeError`s on `transport.complete(...)`, queried `transport.getStatus(file.uploadId)` once, and returned `validateReceipt(status.receipt, file)` if `status.state === 'complete'`.
   - **TypeScript strict typecheck errors (`npm run typecheck`)**:
     - *Cause*: (1) `src/journal-store.ts` `.catch(error => this.failed = error)` returned `unknown` instead of `void`; (2) `src/transport.ts` passed `Buffer<ArrayBufferLike>` to `fetch` `BodyInit`; (3) `src/cli.ts` accessed `.code` on `unknown`/`Error`.
     - *Fix*: Used `{ this.failed = error; }` block in `src/journal-store.ts`, wrapped `Buffer` in `new Uint8Array(body)` in `src/transport.ts`, and narrowed `error instanceof CliError ? error.code : 'unknown'` in `src/cli.ts`.
   - **Lazy part generation & remote session identity validation (`node scripts/review-invariants.ts`)**:
     - *Cause*: `plans.flatMap` materialized all part jobs up front; `status.file_size`, `status.file_sha256`, and `status.part_size` were not checked on resume.
     - *Fix*: Added generator `pendingParts(plans)` and `validateSession(status, file)` in `src/resume.ts`.
   - **Integration failures on exit code for `destination_mismatch` and `SIGINT_during_request`**:
     - *Cause*: `destination_mismatch` exited with `1` instead of `3`; `push.ts` did not `await store.settled()` in a `finally` block when `parallel(...)` threw on abort.
     - *Fix*: Mapped `journal_invalid`, `journal_unsupported`, `destination_mismatch`, and `session_mismatch` to exit code `3` in `src/exit-code.ts`, and wrapped `parallel(...)` in `try { ... } finally { await store.settled(); }` in `src/push.ts`.
